# Протокол испытания руководства

## Режим испытания

**Режим:** аналитическое испытание по модели интерфейса.  
**Основание:** стенд не предоставлен. Испытание проведено по `data/operator_observations.md`.  
**Ограничение:** проверяет пропуски и неоднозначность текста, но не подтверждает реальное поведение приложения. Отзыв партнёра не выдумывался.  
**Важно:** поле «нажал» как факт реальной работы не заполняется. Все наблюдения ниже — проверка по модели интерфейса.

## Протокол замечаний

| Сценарий | Шаг | Ожидание | Наблюдение по модели интерфейса | Требуемое уточнение |
|---|---|---|---|---|
| 1 | Создание без вложений | После «Отправить» есть номер и ссылка «Открыть» | В наблюдениях есть сообщение «Заявка LAB-104 создана» со ссылкой «Открыть» | Указать, что номер в учебном сеансе может отличаться и берётся из сообщения |
| 1 | Повторное открытие по номеру | Заявку можно найти по номеру в списке | В списке есть поле «номер» и фильтр «Мои», но отдельный поиск по номеру не описан | Не выдумывать поиск; указать поиск строки по полю «номер» и фильтр «Мои» |
| 2 | Четвёртый файл | Показано «Можно приложить не более 3 файлов», текст остаётся | Сообщение и сохранение текста описаны; способ удаления файла из поля «Вложения» не описан | Добавить остановку, если нет явного способа удалить файл; не угадывать кнопку |
| 2 | Исправление отказа | После удаления лишнего файла можно отправить | Модель не показывает конкретный элемент удаления | Запретить обход лимита и переименование файла; при отсутствии элемента — поддержка |
| 3 | Сетевой тайм-аут | Показано «Не удалось получить ответ. Проверьте список заявок перед повтором» | Сообщение есть; переход из формы к списку явно не описан | Добавить два исхода: запись найдена / не найдена; не повторять отправку до проверки |
| 3 | Исход «не найдена» | Нужно сохранить текст и обратиться в поддержку | В модели нет детального порядка поддержки | Не выдумывать контакты; указать «разрешённый порядок поддержки учебного стенда» |
| 4 | Поиск назначенной заявки | Техник видит назначенные заявки | Есть фильтр «Назначенные» и карточка `LAB-101` | Указать фильтр «Назначенные» и проверку статуса `open` |
| 4 | Завершение | Переход в `resolved` требует непустого комментария | В наблюдениях сказано «с обязательным комментарием», но точное название поля не приведено | Не выдумывать название; писать «обязательное поле комментария» |
| 5 | Отказ доступа | Показано «Нет доступа к этой заявке» и «К списку» | Экран описан; причина отказа не указана | Не указывать причину; добавить запрет на обход и возврат к разрешённому фильтру |

## Повторная проверка изменённых мест

| Изменённое место | Проверка после правки | Результат |
|---|---|---|
| Сценарий 2, удаление четвёртого файла | В тексте нет выдуманной кнопки удаления; есть остановка при отсутствии способа удаления | Пройдено по модели |
| Сценарий 3, два исхода | Явно описаны «запись найдена» и «запись не найдена»; повтор запрещён до проверки | Пройдено по модели |
| Сценарий 4, комментарий | Нет выдуманного названия поля; сказано «обязательное поле комментария» | Пройдено по модели |
| Сценарий 5, отказ доступа | Есть «К списку», запрет обхода и возврат к «Мои»/«Назначенные» | Пройдено по модели |

## Список вопросов для будущего читателя

1. Каким штатным элементом удаляется уже выбранный файл в поле «Вложения»?
2. Как из формы «Новая заявка» после сетевого сообщения перейти к экрану «Заявки», если «Отмена» не используется?
3. Есть ли на экране «Заявки» поиск по номеру, или номер ищется только визуально по списку?
4. Как точно называется обязательное поле комментария при завершении заявки?
5. Что именно считается «разрешённым порядком поддержки» на учебном стенде?

## Ограничение проверки

Проверка одним автором не заменяет испытание с партнёром на стенде. Она обнаруживает пропуски и двусмысленность, но не подтверждает фактическое поведение приложения.
